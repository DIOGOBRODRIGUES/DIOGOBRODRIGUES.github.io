BLOCO 1

Props

Como um componente recebe informações e ações de outro

Tempo sugerido: 1 minuto. Transição: do comportamento visível do favorito para o fluxo de dados no código. Pergunte: “Quem sabe o número de favoritos?” A resposta é App, que detém favoriteIds.

CONCEITO

Props são entradas do componente

O componente pai fornece valores ao filho por atributos JSX.

<Header favoritesCount={favoriteIds.length} /> O filho lê favoritesCount; quem mantém o estado é App.

Props podem levar números, objetos, arrays e funções.

Tempo sugerido: 5 minutos. Defina props como dados recebidos pelo componente. Explique que, no Pulso Campus, App calcula favoriteIds.length e o passa ao Header. Pergunte se Header deve modificar a prop. Resposta: não; props são tratadas como entradas somente de leitura. Confusão comum: chamar props de “estado do filho”. Fonte: https://react.dev/learn/passing-props-to-a-component

BLOCO 3

localStorage

Como recuperar um dado relevante após recarregar

Tempo sugerido: 1 minuto. Transição: as rotas funcionam e o favorito muda, mas a execução termina no reload. Peça que a turma preveja o que acontecerá antes de atualizar.

BUG PARA PREVER

O favorito desapareceu

☆ Salvar ★ Salvo ↻ Reload ☆ Salvar

O estado mudou. Por que a nova execução não se lembra dele?

Tempo sugerido: 5 minutos. Faça a demonstração no esqueleto. Antes de recarregar, peça previsão. Resposta: useState([]) inicia novamente com array vazio; o valor anterior existia apenas em memória. Explique que isso é esperado. Pergunte onde guardar um dado pequeno do próprio navegador. Resposta: localStorage. Não diga que o React recarrega a página; é o navegador que recarrega o documento quando o usuário pede reload. Fonte: https://react.dev/reference/react/useState e https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage

CONCEITO

localStorage guarda strings

Estado React['game-jam-relampago']array em memória
⇄
localStorage'["game-jam-relampago"]'texto no navegador

JSON.stringify grava. JSON.parse recupera.

Tempo sugerido: 5 minutos. Mostre a diferença entre o array JavaScript e o texto JSON. Peça que a turma diga o tipo de retorno de getItem: string ou null. Explique que setItem converte valores para string e, sem JSON.stringify, um array de IDs vira uma string inadequada para recuperação estruturada. Confusão comum: pensar que localStorage armazena objetos JavaScript diretamente. Fontes: https://developer.mozilla.org/en-US/docs/Web/API/Storage/setItem e https://developer.mozilla.org/en-US/docs/Web/API/Storage/getItem

LEITURA INICIAL

O estado começa com o dado salvo

function readStoredArray(key) {
  const storedValue = localStorage.getItem(key)
  if (!storedValue) return []
  return JSON.parse(storedValue)
}

Versão mínima para entender o fluxo; o projeto completo acrescenta validação e try/catch.

useState(() => readStoredArray(FAVORITES_KEY))
Tempo sugerido: 7 minutos. Explique chave, getItem, ausência do dado e JSON.parse. A função passada a useState calcula o valor inicial ao montar o componente. Abra App.jsx para mostrar a função real com try/catch e Array.isArray. Pergunta: “O que ocorre se alguém inserir um JSON inválido na chave?” Resposta: JSON.parse lança erro; a versão completa trata e retorna []. Fonte: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/parse e https://react.dev/reference/react/useState

GRAVAÇÃO APÓS MUDANÇA

O efeito sincroniza o novo valor

useEffect(() => {
  localStorage.setItem(FAVORITES_KEY, JSON.stringify(favoriteIds))
}, [favoriteIds])

App.jsx · o efeito reage a mudanças em favoriteIds

O clique muda o estado. O efeito grava a representação em texto.

Tempo sugerido: 6 minutos. Mostre o uso mínimo de useEffect para sincronizar com um sistema externo ao React. Pergunte se chamar setItem com favoriteIds sem JSON.stringify recuperaria o mesmo array. Resposta: não. Não aprofunde teoria geral de efeitos. Lembre que a leitura inicial vem antes da primeira gravação, evitando perder o valor salvo. Fonte: https://react.dev/reference/react/useEffect e https://developer.mozilla.org/en-US/docs/Web/API/Storage/setItem
