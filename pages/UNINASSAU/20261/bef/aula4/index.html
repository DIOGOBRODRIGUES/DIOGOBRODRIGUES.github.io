1. Introdução e Funcionalidades do Axios

O Axios é um cliente HTTP poderoso que fornece uma API simples e fácil de usar para realizar requisições HTTP. Ele é construído sobre a Promise API nativa do ES6, e cada requisição retorna uma Promise.

Uma de suas características principais é ser isomórfico, o que significa que o mesmo cliente pode ser usado tanto no navegador (frontend) quanto no Node.js (backend). Isso o torna uma excelente escolha para equipes que trabalham em ambas as frentes, permitindo uma API consistente que reduz a complexidade do código.

2. O Objeto de Resposta (Response Schema)

Toda requisição feita com o Axios, quando bem-sucedida, é resolvida com um objeto de resposta que possui uma estrutura padronizada e consistente. Conhecer esse esquema é essencial para extrair os dados corretos no backend.

  • data: Contém os dados fornecidos pelo servidor (o corpo da resposta).
  • status: O código de status HTTP retornado pelo servidor, como 200, 404, etc.
  • statusText: A mensagem correspondente ao código de status (ex: "OK", "Not Found").
  • headers: Os cabeçalhos HTTP de resposta. Note que todos os nomes de cabeçalhos de resposta são convertidos para letras minúsculas.
  • config: As configurações fornecidas ao Axios no momento da requisição (URL, timeout, params).

3. Criando Instâncias Personalizadas

Em aplicações complexas que se comunicam com mais de uma API, a melhor prática é criar uma instância separada por serviço usando a função axios.create(). Isso evita a repetição da URL base em todas as chamadas.

Você pode configurar valores padrão que serão aplicados a todas as requisições que utilizarem aquela instância. O Axios aplica uma ordem de precedência na configuração: padrões da biblioteca -> padrões da instância -> configuração passada na requisição específica.

// Criando uma instância dedicada a um serviço interno
const internalApi = axios.create({
  baseURL: "https://api.internal.example.com",
  timeout: 5000,
  headers: { "X-Custom-Header": "foobar" }
});

// A requisição abaixo usará a baseURL e o timeout definidos acima
const { data: users } = await internalApi.get("/users");

4. Interceptadores (Interceptors)

Os interceptadores são um mecanismo poderoso, semelhante aos middlewares do Express.js, que permitem interceptar e modificar as requisições antes de serem enviadas, e as respostas antes de chegarem ao bloco `then` ou `catch` do seu código.

Eles são extremamente úteis para tarefas transversais (cross-cutting), como logging, tratamento global de erros e, principalmente, autenticação via Tokens JWT (Bearer). O local ideal para anexar um token na requisição de forma que seja lido "fresco" a cada chamada é através de um interceptador de requisição:

api.interceptors.request.use((config) => {
  const token = localStorage.getItem("access_token");
  if (token) {
    // Adiciona o token no cabeçalho Authorization
    config.headers.set("Authorization", `Bearer ${token}`);
  }
  return config;
});

5. Tratamento de Erros e Recuperação

Por padrão, o Axios resolve a Promise para qualquer resposta 2xx e a rejeita (causando um erro) para qualquer código fora dessa faixa (ex: 400 ou 500). A classe principal gerada quando ocorre uma falha é o AxiosError.

Para inspecionar de forma segura se o erro capturado no seu `catch` provém do Axios e possui as propriedades específicas da biblioteca (como error.response), você deve utilizar o verificador axios.isAxiosError().

try {
  await axios.get("/api/recurso");
} catch (error) {
  if (axios.isAxiosError(error)) {
    // error.response e error.config estão garantidos aqui
    console.error("Erro HTTP:", error.response?.status);
  } else {
    // Erro de programação que não tem relação com o Axios
    throw error;
  }
}

6. Cancelamento e Timeouts

Em sistemas reais, uma requisição à rede pode falhar ou travar. Sem um tempo limite determinado na propriedade timeout (passado via config da requisição), uma requisição travada pode ficar pendente indefinidamente.

Se você precisar cancelar manualmente uma requisição em andamento, o Axios suporta a API padrão AbortController. A antiga classe CancelToken está descontinuada e seu uso não é recomendado. Quando um erro for disparado pelo cancelamento explícito, ele conterá o código de erro interno ERR_CANCELED.

7. Upload de Arquivos e Submissão de Formulários

Os métodos postForm, putForm e patchForm configuram automaticamente o cabeçalho `Content-Type` para `multipart/form-data`. Eles são a maneira recomendada para fazer upload de arquivos ou submeter formulários HTML.

Você pode rastrear o andamento de um envio no navegador usando a função de retorno onUploadProgress.

Atenção: A captura do progresso de upload via FormData não é atualmente suportada em ambientes Node.js.

8. Trabalhando com Promises

O Axios é totalmente construído em cima da API nativa de Promises do ES6, o que significa que cada requisição retorna uma Promise. A abordagem recomendada para a maior parte do código é a utilização do async/await, pois faz o código assíncrono parecer síncrono e muito mais legível.

Como o retorno é uma Promise padrão, você pode utilizar o utilitário Promise.all para realizar requisições paralelas e aguardar todas concluírem.

// Exemplo de Requisições Paralelas
const [users, posts] = await Promise.all([
  axios.get("/api/users"),
  axios.get("/api/posts"),
]);
console.log(users.data, posts.data);
Dica Avançada: O Promise.all será rejeitado assim que qualquer uma das requisições falhar. Caso você deseje lidar com falhas parciais e resgatar os sucessos isoladamente, a documentação recomenda a utilização do Promise.allSettled.

9. Integração com TypeScript

O Axios já vem com definições de TypeScript nativas de fábrica ("out of the box") através do arquivo index.d.ts. Você pode importar os tipos diretamente da biblioteca, garantindo maior segurança e auto-completar na sua IDE.

Alguns dos tipos mais importantes incluem AxiosRequestConfig, AxiosResponse e o AxiosError. Você pode utilizar parâmetros de tipo genérico (Generics) na requisição para informar ao TypeScript qual será a estrutura (shape) dos seus dados de retorno.

import axios, { AxiosResponse } from "axios";

// Definindo a interface da nossa resposta
type Post = {
  userId: number;
  id: number;
  title: string;
  body: string;
};

// Utilizando Generics para tipar a resposta
const getPost = async (id: number): Promise<Post> => {
  const response = await axios.get<Post>(
    `https://jsonplaceholder.typicode.com/posts/${id}`
  );
  return response.data; // O TS sabe automaticamente que isso é do tipo "Post"
};
Aviso sobre Interceptadores: Na versão 1.x do Axios, ao tipar interceptadores de requisição, você deve obrigatoriamente utilizar o tipo InternalAxiosRequestConfig (e não o AxiosRequestConfig padrão).

Além disso, o Axios fornece suporte embutido para restringir o tipo de um erro utilizando axios.isAxiosError<ApiError>(error), que ajuda a inspecionar atributos do erro de forma tipada, como error.response?.data.message.
